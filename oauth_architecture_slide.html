🔐 OAuth & Single Sign-On (SSO) Architecture

Enterprise Identity Flow: Microsoft Entra ID (Azure AD) ↔ Google Cloud Vertex AI

Microsoft Entra ID Cloud Run / Vertex AI Zero-Prompt SSO
End-to-End Authentication & Request Pipeline OAuth 2.0 / OIDC Bearer Token
STEP 1: CLIENT Office.auth.getAccessToken() Silently requests signed Entra ID JWT using pre-authorized tenant app scope.
→
STEP 2: TRANSPORT Bearer Token Request Passes JWT in Authorization: Bearer header to Cloud Run gemini-proxy.
→
STEP 3: PROXY AUTH JWKS Validation & Claims Validates signature via Microsoft public keys, verifies Tenant ID, extracts user email.
→
STEP 4: VERTEX AI ACL-Aware Generation Backend calls Vertex AI using GCP Service Account with user context for grounded search.
🪪

Office 365 Client SSO

microsoft-addin & manifest.xml
  • Native Entra ID Binding: Manifest declares <WebApplicationInfo> with Azure App Registration ID.
  • Zero-Prompt Experience: Pre-authorized Office client IDs eliminate consent prompts for corporate users.
  • Fallback Mechanism: Graceful degradation to MSAL.js popup dialog if SSO is restricted by client host.
🛡️

Backend JWT Verification

geminiproxy/index.js
  • Stateless Key Discovery: Uses jwks-rsa to cache & verify Microsoft signing keys dynamically.
  • Tenant Allowlisting: Validates tid (Tenant ID) to restrict access to authorized enterprise domains.
  • User Audit & Telemetry: Injects verified req.user.email into Cloud Logging & quota meters.
🔒

ACL Grounding & Security

Vertex AI & StreamAssist
  • ACL-Aware Search: Propagates user identity to Vertex AI Search ensuring users only retrieve permitted docs.
  • Least-Privilege IAM: Cloud Run connects via Workload Identity / Service Account with roles/aiplatform.user.
  • Cross-Cloud Trust: Secure bridge linking Microsoft corporate logins directly to Google GenAI capabilities.
