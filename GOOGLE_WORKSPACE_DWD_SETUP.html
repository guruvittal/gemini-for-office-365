Google Cloud & Google Workspace

Domain-Wide Delegation (DWD) Setup Guide

Integration: Gemini Enterprise for Microsoft Office 365  |  Target: End-User Google Drive Grounding

1. Overview & Purpose

To enable the Gemini Enterprise Microsoft Office 365 Add-in to query and ground responses on users' personal and shared Google Drive files, the Google Workspace Super Administrator must authorize the backend Service Account once in the Google Workspace Admin Console.

Prerequisites
• Role: Google Workspace Super Administrator
• Console: admin.google.com
• Estimated Time: 2 minutes (one-time setup for the domain)

2. Step-by-Step Authorization Steps

1 Navigate to Domain-Wide Delegation

  1. Open admin.google.com and sign in as the Google Workspace Super Admin.
  2. In the left menu, navigate to: Security ➔ Access and data control ➔ API controls.
  3. Scroll down to the Domain-wide delegation pane and click Manage Domain-Wide Delegation.
  4. Click Add new.

2 Enter Client ID and OAuth Scopes

Fill out the authorization form with the exact parameters below:

Client ID (OAuth 2 Client ID):

110472144010421785275

OAuth Scopes (comma-separated):

https://www.googleapis.com/auth/cloud-platform,https://www.googleapis.com/auth/drive.readonly
OAuth Scope Purpose & Access Level
https://www.googleapis.com/auth/cloud-platform Allows Discovery Engine / Gemini Enterprise to query datastores with user identity context.
https://www.googleapis.com/auth/drive.readonly Grants read-only access for search and citation of documents the user has permissions to view.

3 Save and Confirm

  1. Click Authorize.
  2. Confirm that Client ID 110472144010421785275 appears in the API Clients table.

3. Security & Access Control Model

  • Principle of Least Privilege: The delegation only grants drive.readonly. The backend cannot create, modify, delete, or share any files.
  • Strict ACL Enforcement: Gemini Enterprise only returns search results for files that the individual requesting user already has permissions to access in Google Drive.
  • Automated & On-Demand: Access tokens are generated on-the-fly, encrypted in transit, cached in-memory for 1 hour maximum, and never stored permanently.
