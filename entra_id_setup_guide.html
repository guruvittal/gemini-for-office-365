Microsoft Entra ID Configuration Guide

Gemini Enterprise Office 365 Add-in (PowerPoint, Word, Excel, Outlook)

Admin Setup Guide
Purpose: This guide outlines the steps required for a Microsoft Entra ID (Azure AD) administrator to register and expose the API for the Gemini Enterprise Office 365 Add-in to enable seamless Single Sign-On (SSO).
1

Create App Registration

  1. Sign in to the Microsoft Entra admin center (entra.microsoft.com).
  2. Navigate to Identity > Applications > App registrations.
  3. Click + New registration.
  4. Name: Gemini Enterprise Office Add-in
  5. Supported account types: Select Accounts in this organizational directory only (Single tenant).
  6. Redirect URI: Leave blank.
  7. Click Register.
2

Set the Application ID URI

Office 365 SSO strictly requires the Application ID URI to match the hosting backend domain.

  1. In the left navigation menu, select Expose an API.
  2. Next to Application ID URI, click Set (or Edit).
  3. Enter the URI in the following exact format:
    api://gemini-frontend-16933400417.us-central1.run.app/<APPLICATION_CLIENT_ID>
    (Replace <APPLICATION_CLIENT_ID> with the Application (client) ID from Step 1).
  4. Click Save.
3

Define the access_as_user Scope

  1. Still on the Expose an API page, click + Add a scope.
  2. Scope name: access_as_user
  3. Who can consent: Admins and users
  4. Admin consent display name: Access Gemini Enterprise as user
  5. Admin consent description: Allows Office add-in to authenticate the signed-in user against Gemini Enterprise.
  6. State: Enabled
  7. Click Add scope.
4

Pre-Authorize Microsoft Office Clients

Pre-authorizing Microsoft client IDs allows silent SSO without repeated consent popups for users.

  1. Still on the Expose an API page, scroll to Authorized client applications.
  2. Click + Add a client application and add the two authorized Office clients:
Application / Client Type Client Application ID (GUID) Authorized Scopes
Office on the Web ea5a67f6-b6f3-4338-b240-c655ddc3cc8e Check access_as_user
Modern Office Desktop / PowerPoint / Outlook bc59ab01-8403-45c6-8796-ac3ef710b3e3 Check access_as_user
5

Enable v2.0 Access Tokens

  1. In the left navigation menu, select Manifest.
  2. Locate the "accessTokenAcceptedVersion" property (or "requestedAccessTokenVersion" under "api").
  3. Change its value from null or 1 to 2.
  4. Click Save.
6

Configure Token Claims

  1. In the left navigation menu, select Token configuration.
  2. Click + Add optional claim.
  3. Select Access as the token type.
  4. Select the check boxes for: email, upn, and preferred_username.
  5. Click Add (accept any Microsoft Graph permission prompt).
7

API Permissions & Admin Consent

  1. In the left navigation menu, select API permissions.
  2. Ensure User.Read, openid, profile, and email are present under Microsoft Graph.
  3. Click Grant admin consent for <Your Organization> and confirm.

📋 Information Required from Administrator

Once completed, please reply with the following values from the App Registration Overview page:

  • Application (client) ID: <e.g. 74a2fdc6-7d78-4ffa-99be-e70e2eab33a0>
  • Directory (tenant) ID: <e.g. 464c0986-459d-42b9-a68d-aff41ccd3b16>
