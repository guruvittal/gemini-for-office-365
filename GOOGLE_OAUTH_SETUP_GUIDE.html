Google OAuth 2.0 Web Client Setup & Deployment Ordering Guide

3-Legged User OAuth Configuration for Cloud Identity / Google Workspace

Environment Target: Gemini Enterprise configured with Cloud Identity / Google Identity (GSUITE)
GCP Project (Gemini Enterprise): jeansson-gem-ent-ci • Cloud Run Project: agentspace-452714
Core Architecture: 3-Legged Google User Consent (Zero Domain-Wide Delegation / DWD Required)
CRITICAL DEPLOYMENT ORDERING DEPENDENCY:
Google OAuth 2.0 Web Client configuration requires specifying the exact Authorized JavaScript Origin (https://<gemini-frontend-url>) and Authorized Redirect URI (https://<gemini-frontend-url>/google-callback.html).
You must deploy the frontend and proxies first to obtain your canonical Cloud Run URL before creating the OAuth Client in Google Cloud Console.

Phase 1: Deploy Core Cloud Run Services (Frontend First)

  1. Deploy Backend Proxy (geminiproxy): 
    gcloud run deploy askgemini-proxy --source ./geminiproxy --project agentspace-452714 --region us-central1 --no-allow-unauthenticated
  2. Deploy Auth Gateway (authproxy): 
    gcloud run deploy auth-proxy --source ./authproxy --project agentspace-452714 --region us-central1 --allow-unauthenticated
  3. Deploy Microsoft Add-in Host (gemini-frontend): 
    gcloud run deploy gemini-frontend --source ./microsoft-addin --project agentspace-452714 --region us-central1 --allow-unauthenticated
  4. Capture the Canonical Frontend URL: https://gemini-frontend-16933400417.us-central1.run.app

Phase 2: Configure Google Cloud OAuth Client in Gemini Enterprise Project

In Google Cloud Console, select the project hosting your Gemini Enterprise instance (e.g. jeansson-gem-ent-ci):

1. Configure OAuth Consent Screen

  1. Navigate to APIs & Services → OAuth consent screen.
  2. Select User Type: Internal (allows all enterprise users to authenticate immediately).
  3. Set App name: Gemini Enterprise for Office 365.
  4. Enter your administrator email for User support email and Developer contact.
  5. Click Save and Continue.

2. Configure Data Access (Scopes)

  1. Under the Data Access / Scopes tab, click Add or Remove Scopes.
  2. Select: openid, .../auth/userinfo.email, .../auth/userinfo.profile.
  3. In Manually add scopes, paste: 
    https://www.googleapis.com/auth/cloud-platform,https://www.googleapis.com/auth/drive.readonly
  4. Click Add to Table → Update → Save.

3. Create OAuth 2.0 Web Client ID

  1. Navigate to APIs & Services → Credentials → + CREATE CREDENTIALS → OAuth client ID.
  2. Select Application type: Web application.
  3. Set Name: Gemini Office 365 Web Client.
  4. Authorized JavaScript origins: Enter your deployed frontend domain: 
    https://gemini-frontend-16933400417.us-central1.run.app
  5. Authorized redirect URIs: Enter the callback page URL: 
    https://gemini-frontend-16933400417.us-central1.run.app/google-callback.html
  6. Click CREATE and copy your new Client ID (e.g., 497524937986-...apps.googleusercontent.com).

Phase 3: Inject Client ID into Auth Gateway (Zero Hardcoding)

The Client ID is delivered to the frontend dynamically via /api/config on auth-proxy, keeping frontend bundles completely generic:

gcloud run services update auth-proxy \
  --project agentspace-452714 \
  --region us-central1 \
  --update-env-vars GOOGLE_OAUTH_CLIENT_ID="497524937986-66oh05fskrkufpv2he7fb00fmpd4nlt9.apps.googleusercontent.com"
Verify Configuration: curl -s https://auth-proxy-16933400417.us-central1.run.app/api/config
Returns: {"google_oauth_client_id": "497524...", "user_auth_mode": "cloud_identity", ...}

Phase 4: End-User Runtime Flow & Token Handling

  1. Interactive Consent: User opens the add-in in Word/PowerPoint/Excel and clicks 📁 Connect Drive.
  2. Office Dialog API: Add-in opens google-auth.html via Office.context.ui.displayDialogAsync with login_hint prefilled.
  3. Google Consent: User grants read-only access to their Google Drive files.
  4. Message Parent Callback: google-callback.html parses #access_token=ya29... and transmits it to the taskpane using Office.context.ui.messageParent.
  5. Grounded Search: When asking questions, X-End-User-Google-Token is forwarded to geminiproxy, which executes Discovery Engine streamAssist with Authorization: Bearer <ya29...> and toolsSpec: { vertexAiSearchSpec: {} }.
